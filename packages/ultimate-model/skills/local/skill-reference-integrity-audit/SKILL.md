# 技能引用完整性审计

## 何时用

技能正文被移动、回灌、合并、换层之后；或分发前检查。

## 四步

1. **提取**：正文里的 Markdown 目标 + 反引号里的相对路径。**跳过**代码块、行内示例、`http(s)`、锚点。
2. **解析**：相对路径按**该文件所在目录**解析（不是 cwd，也不是仓库根——这条错了会报一堆假悬空）。
3. **归因**，只有三类：
   - 从未落盘：写了但从来没有这个文件 → 改指向真实入口或改写为文本；
   - 曾存在已丢：文件被移走/被删 → 先查是不是被挪进停用目录，再决定移回还是改指向；
   - 指向包内布局：链接是按分发包的目录结构写的（`../../../preset/...`），搬到目标机 home 必然悬空 → 改写成"包内相对路径"的**纯文本**，不要留成链接。
4. **收口**：全量重跑一次，要求 `broken = 0`；并把"通过"的口径写清（检查了哪些根、多少份文件）。

## 判据与反例

- 判据：脚本输出 `broken_links=0` 且**扫描文件数 > 0**（0 份文件也是 0 悬空，那是空跑假绿）。
- 反例：只查"文件存在"不查语义——链接指到旧版归档，文件在但内容过时；
- 反例：把归档当能力——停用目录/历史备份里的同名文件会让"能力还在"看起来成立；
- 反例：并发会话同时移动技能目录，导致本轮判为"丢失"，实际是对面刚挪走 → 先查停用目录与最近改动时间，再下结论。
