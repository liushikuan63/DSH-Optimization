# 规则体系冲突审计

## 六维交叉

| 维度 | 找什么 |
|---|---|
| 全局规则 | 各自权威边界、篇幅预算、例外条款 |
| 每轮注入块 | 是否与全局规则重复（重复即漂移起点） |
| 门禁脚本 | 判据是否与文档表述一致；有没有只写文档不写判据的条目 |
| 领域技能 | 同域两套口径、触发词互抢 |
| 记忆条目 | 旧结论是否仍被当作当前事实 |
| 分享包 | 分发版与目标机版是否被误当成同一份 |

## 三类判定

1. **同义复写**：同一约束写了两遍 → 删一处，留单一真源，另一处改为指路。
2. **口径漂移**：两边都写了但取值不同（次数、阈值、路径、允许范围）→ 先查现场取真值，再统一。
3. **真冲突**：两条规则在具体场景下给出相反动作 → 按适用范围/权限边界裁决，写清哪条优先、哪条是例外。

## 报告与收口

每条给：文件:行、原话摘录、与谁冲突、**行为影响**（在什么操作上会出什么后果）、建议改文（可直接粘贴）、以及**是否扩权**（新表述是否放宽了授权/验证标准——放宽必须单独标注并请人裁决）。

- 只读出报告，不顺手改；批准后按条改，改完复跑周检与提及扫描。
- 不以"规则变多"为成绩：审计的产出通常是**更少**的条目。

## 反例

- 只比对措辞不做行为推演 → 报出一堆"同义不同字"的假冲突；
- 把"更具体"当成"可越权"（项目细则不得放宽安全边界）；
- 改完不跑门禁，把新冲突带进下一轮。
