# 前端通用规则

> 来源：Qoder rules/frontend.md（**去掉「动效与可视化交付基线」与「主题切换」两节**，那两组已由技能 `frontend-motion-delivery` 承接），2026-10-13 移植。

## 0. 与其它前端技能的分工（先别重复加载）

| 要做的事 | 加载 |
|---|---|
| 动效件 / SVG 插画 / 昼夜主题 / 平铺滚动 | `frontend-motion-delivery` |
| 页面改动收尾验收（真跑 dev server + 截图） | `verify-ui-in-browser` |
| hooks 式 React / Vue 3 的组件写法 | `react` / `vue` |
| 设计映射 / 请求层 / 国际化 / 无障碍 / 语义判据 | **本技能** |

## 一、设计 → 代码映射（有意为之，不是"看着像"）

| 设计侧 | 代码侧 |
|---|---|
| frame / auto layout | `flex` / `grid` |
| component + variant | 组件 API + props |
| local styles | design tokens（CSS 变量） |
| prototype 交互 | 真实状态与路由 |

- **设计阶段就带入实现约束**（握手优先于交接）；原型要**如实标注**还需生产化的工作。
- 遵循项目既有框架与目录约定，**不擅自引入第二套**状态管理 / 请求库 / 样式方案；依赖版本以 lockfile 为准，不手工改版本号绕过冲突。
- 判据：页面结构里每个容器都能对应到设计上的一个 frame 或组件；写不出对应关系的容器，要么删要么说明理由。

## 二、类型与契约

- 严格模式为准，**不开 `any` 后门**（必要时 `unknown` + 收窄）；**外部输入在边界处校验，内部信任类型**。
- 状态用**判别联合**表达，不用一堆可选布尔字段拼状态机（`{loading, ok, error}` 同真同假就是隐患）。
- **前后端契约变更必须同步**：字段改名 / 改类型时两端一起改，改完跑一次类型检查。判据：类型检查退出码 0。

## 三、请求层（三个反复踩的坑）

1. **取消 ≠ 失败**：同 URL 去重（`cancelToken` / `AbortController`）会 abort 先发的请求——UI 必须用 `isCancel(e)` 识别，**取消不弹错、不清空列表**；并加**请求序号守卫**，防迟到响应覆盖界面。
2. **"请求次数"断言先数清实现**：带重试的封装常把"首调"放在预算之外（总数 = 1 原请求 + 1 首调 + `maxRetries`）；业务错误码（HTTP 200 且 `code != 200`）**不触发**重试。**先跑一次夹具数出真值再写断言**。
3. 失败会**逐条弹通知**——**截图前先关掉**，否则截图被通知盖住，看不出版面问题。

## 四、多语言界面

- 长语言（如阿姆哈拉语）在紧凑位（tag / 窄列 / 竖排 / 图例）用**专用短键**，**不复用** `common.*` 长标签。
- 服务端渲染文案**不在落库时拼句**：存 `messageKey` + `messageParams`，双端同键渲染；新增类型时**两端补文案**。
- 列头用 `min-width`（写死宽度会被长语言撑破或被截断）。
- 判据：切到最长语言后，紧凑位不溢出换行、列头不截断文字。

## 五、交互无障碍（表单 / 弹窗 / 菜单，**只查受影响组件**）

- 可操作元素优先**原生 `button` / `link`**（`div` + `onClick` 不算键盘可用）。
- 输入有可访问名称、`label` 正确关联；**`placeholder` 不替代 `label`**；错误 / 帮助信息关联到输入；**只改颜色不能传达错误**。
- 弹窗核对：可访问名称、打开后焦点、Tab 范围、`Escape` 关闭、关闭后**焦点回原位**；真实模态还要验证**背景不可被键盘 / 指针操作**（`aria-modal` 只表语义）。
- 图标按钮有名称、装饰图不重复朗读；表单中非提交按钮**显式写 `type`**（否则会意外提交）；链接保留真实地址。
- 菜单与 tab 按**所选组件模式**的键盘约定，不把所有浮层套同一组角色。
- **自动化规则判定不了完整屏幕阅读器体验**——没有真实键盘 / 辅助技术验收时要主动说明这条边界。

## 六、语义判据取数据字段，不从几何 / 坐标反推

- 上下游 / 父子 / 收敛方向**一律读边类型等数据字段**（多套布局下 X 坐标语义可能相反）。
- 非要用坐标就先查 `layoutMode` 并**显式分支**。
- 反例：用"x 坐标更大 = 下游"判流程方向——换个 `layoutMode` 结论就反了。
- 二级信息优先**弹窗**承载，别内联撑高主面板。
