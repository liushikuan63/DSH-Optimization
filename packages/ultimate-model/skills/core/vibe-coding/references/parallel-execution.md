# 并行任务与唯一集成

先由当前模型判断任务能否拆成独立读域/写域、依赖是否已稳定、并发是否有实际收益。并行是实施方式，不提供额外权限、费用或外部发送授权。

- 只读审查可并行，结果需区分来源和验证范围。多个写任务先核对实际 Git root、HEAD、dirty/暂存区、worktree common dir 和任务归属；不 reset/stash/clean 用户工作。需要隔离时使用当前环境已有能力创建 worktree 或任务副本。
- 每个写任务明确 ownedPaths、基线、依赖、验收和禁止修改项；同一文件、共享接口、数据库迁移、锁文件、生成物、构建输入、任务账本与最终集成保持唯一写入者。跨文件仍可能共享产物，不能只按文件名认定独立。
- 派发使用宿主当前可用工具、参数和真实并发上限。由模型选择足够可靠的可用模型与思考强度；能力不明先核对，不静默降级验收、不自动购买额度或换账号。
- 子任务提交具体变更和本轮证据，`READY_FOR_REVIEW` 只表示可审查。集成者核对逐提交 ownedPaths、差异和依赖，做合并预演；实际集成并通过相关门禁后才记为已集成/已验收。
- 下一波依赖任务必须从已集成的新基线开始；前一波接口尚未稳定时，不让后续任务按猜测写入。失败保留可恢复改动，继续独立可做部分，不覆盖其他写者新内容。
- 前台输入与同一沙箱操作只能有一个操作者；复用精确窗口/会话，读回结果。派发成功或无报错不能当成实际完成。

状态可沿项目约定使用 NOT_STARTED → RUNNING → READY_FOR_REVIEW → INTEGRATED → VERIFIED。交接至少记录目标/授权、基线与产物hash、运行实例归属、已验/未验、首红、下一条具体动作和写入权；恢复时重新核对现场。
