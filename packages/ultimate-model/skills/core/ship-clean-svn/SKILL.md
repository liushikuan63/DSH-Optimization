# SVN 提交与交付

先用当前工作副本的 `svn info` 和项目说明核实仓库、分支及生成规则，不继承作者项目的路径、版本串或分支结论。此参考流程不提供提交、发布或部署授权。

1. `svn status` 区分本任务修改、已有修改、生成物和未纳管文件；保护其他任务内容。
2. `svn diff --summarize` 核对清单，再读具体路径的差异；排除凭据、临时文件、调试内容和意外生成物。
3. 根据项目规则确认是否需要更新工作副本，先保护本地修改；无关冲突保留并报告，不自动全量还原。
4. 新源文件仅按明确路径执行 `svn add`；禁止 `svn add --force .`。已经纳管的 target、dist 等仍可能被构建修改，不能一律视为可丢弃。
5. 提交前完成相关验证。`svn commit` 会写入远端仓库，必须具备当前任务适用的明确授权；有授权后按具体路径提交，禁止无路径全量提交。

```text
svn commit -m "<变更与原因>" <本任务源文件路径1> <本任务源文件路径2>
```

版本核对区分页面显示、构建产物名、配置版本和 SVN revision，以目标项目的发布契约与实际产物关联为准。自动生成的版本文件只修改其真源；不要手改生成物。通用修复是否回流其他分支需确认目标和授权，不能由历史分支习惯推导。

凭据不得进入源码、提交说明或交付报告。Base64、编码标记和可逆混淆不等于加密或秘密管理；遵循目标项目受支持的凭据注入与配置方式。发现既有敏感内容时去敏报告并按任务授权处理，不擅自删除或改写无关文件。

提交前阅读相关 `verify-before-claim`；提交说明沿用仓库语言习惯并写清变更原因。工作副本中的未提交修改不能依靠 `svn revert` 恢复，必要时先做有归属、可核验的备份。交付记录 revision、文件范围、实际测试和未验证项，部署与分支合并分别核对。
