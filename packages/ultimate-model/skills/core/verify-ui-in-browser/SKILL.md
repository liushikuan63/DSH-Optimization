# 真实界面验收

## 先找真实入口

1. 读取当前项目的运行说明、package scripts、路由、代理、环境和版本锁定；不默认特定框架、端口或hash模式。
2. 复用正在服务目标页面的正确进程，确认URL与构建来源。启动新服务器不会自动更新另一个实例。
3. 若任务指DSH当前GUI，按运行上下文中的现有URL验证；Vite壳没有宿主boot数据，不是等价替代。
4. 改插件先查该版本HMR契约与构建watcher；未核验watcher不能承诺自动生效。需要重启不擅自停本实例。

## 走完整路径

- 实际打开目标路由，覆盖入口→输入→提交→成功反馈/刷新恢复，不只截初始页。
- 至少走受影响的负向/边界条件，如空输入、非法参数、缺权限、数据为空；不可达权限分支明确标注。
- 截图与Network/DOM证据对应：确认真实请求URL、响应形状、页面结果；不能把守卫链通了说成业务成功。
- 构建、类型检查、lint、组件测试各自有价值，但都不独立证明真实界面可用。
- 版本号/文案/语言/主题从项目配置确定，逐个核对实际支持项，不假定所有项目固定三语。

## 视觉与样式

- 截图取本轮实际运行结果，与需求/基准比对；不能用设计图、mock或无关实例当产物截图。
- 清理本轮测试造成的遮挡再截图，不干扰用户其他窗口；默认后台浏览器/精确窗口路径，不抢前台。
- 主题问题读computed style，而非只凭截图猜颜色。CSS变量在声明元素上解析，子级变量不能改变已计算后继承的值。
- 检查布局裁切、缩放、主题切换、焦点与交互反馈；按当前改动选择范围，不为不相关功能扩展验收。

## 请求负对照

- SPA任意路径可能返回200 HTML；同轮请求真实API与不存在路径，比状态、content-type、响应语义。
- 成功接口有登录/权限前置时，不能用匿名失败响应宣称端到端通过。
- 确认服务进程、端口和构建归属，保留本轮构建退出码；不使用其他会话旧产物证明自己的代码。

## 收尾

- 有可见改动：真实交互＋截图对比才可称视觉通过。
- GUI/工具/权限客观不可得时写“未做视觉验证＋原因”，列具体未测分支和最短复验入口。
- HTTP/构建等替代证据另列，强度不能冒充视觉验收；不说“应该没问题”。
- 历史项目细则可存 references/；只有当前仓库匹配才读取，并重新核对现场，不照搬端口和启动命令。
