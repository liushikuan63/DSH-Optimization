# 技能按需路由与回退

- 当前技能目录是发现入口，不是所有正文的预加载。已列名且相关的技能直接用 skill 加载；已有真实路径可用 read，未读正文不能声称已加载，不重复检索或读取同一路径正文。
- 未列名的领域先用可用的 `jizhi_skill_search` 检索，再 read 命中的真实 SKILL.md；搜索结果只是元数据，不是已加载指令。core、library、用户 .agents 和项目根均可能提供技能。
- 本 router 是缺少发现工具、离线或来源诊断时的回退，不在已完成的搜索前后再叠加同一轮查询。
- 本机已有用户脚本时：`node ~/.dsh/scripts/skill-load.mjs "<关键词>"`。脚本位置先确认，分享包不向 home 复制它。
- 分享包离线检索：`node <包目录>/scripts/skill-load.mjs --bundle-root <包目录> "<关键词>"`。
- 查询实时采集且只读；退出 0 命中、3 无命中、2 为参数/元数据/IO 失败。2 不是“重建即可成功”，先读错误并在授权范围内处理真源，不自行安装、启用或改索引。
- 无命中可换同义词再查一次；仍无则明确未找到，不编造技能。工具认证失败或拒绝不构成换通道绕过边界的授权。
- 同名冲突保留 source/path，按宿主实际优先级核验；索引不是宿主覆盖关系的权威，不静默覆盖同名项。
- 新增低频领域内容默认进 library；全局高频/硬引用元技能留 core。移动前记录脚本、引用和独有能力去向。
- 快照由显式 build 生成；`build-skills-index.mjs --check` 只读检查。快照不是查询真源，不以历史固定数量验收。
- 本机分层恢复必须先预演：`node ~/.dsh/scripts/tier-skills.mjs --restore <名>`；确认范围后带 `--apply`，不能把预演当已恢复。
- 分享包不自动移动用户技能或恢复停用目录；只在显式选择该预设时提供包内入口。

- 能力候选由模型结合当前目标、风险、上下文与已有授权判断，关键词和索引分数只作线索。涉及多个能力或同域替代时，按需读[语义选择与冲突边界](references/capability-selection.md)，不要把匹配当命令或自动安装授权。
