# 按需索引、模型判断与能力冲突

索引只保存名称、描述、来源、层级和真实路径，不预载技能正文。模型基于当前用户目标、领域、风险、已有状态及允许动作判断需要哪项能力；关键词命中、打分、hook 提示只是候选，零命中不是不存在。直接点名的已装能力或已知相关正文直接读取，避免重复发现；需要更多细节再读 references/templates。

对候选给出简短判断：`USE`（相关且可用）、`SKIP`（不相关/替代已覆盖）、`ASK`（尚需用户裁决）、`NEEDS_FACTS`（先补最小现场证据）。无需每轮把所有能力列给用户，也不另调后台模型。跳过候选不能跳过当前项目强制门禁；继续任务复用已有选择，用户纠正后即时调整。

模型负责语义取舍，确定性的路径校验、预像、权限、取消和输入 schema 继续约束执行。推理不能放宽这些门；脚本不冒充完整语义分类器，禁止以模型自评代替实证。当前请求已经授权的必要调用直接推进，不重复确认；需要新费用、外发、停机、缺失能力安装或用户尚未选定的取舍时才提出具体选择，推荐和超时不算批准。

| 能力 | 发现与使用 | 冲突边界 |
| --- | --- | --- |
| 技能/索引 | 实时元数据检索，按需读取正文；同名保留来源 | 不按搜索排序静默覆盖；包、home、项目状态分别核对 |
| 工具分页 | 当前 scope 目录与激活器使用同一配置；成功才激活 | 不重复注册宿主服务，不绕权限过滤；离开模式释放自有分页 |
| 电脑控制 | 先后台接口，再按用户约定选后台/前台入口 | 宿主拥有唯一 provider；预设不私建 native driver，不绕 profile 显式关闭 |
| 模型/网络/MCP | 复用宿主已配置的 provider 和连接；先核版本/schema | 不复制账号/endpoint，不设第二套模型配置，不自动装服务或额外发模型请求 |
| 压缩/接续 | 宿主压缩负责原会话，本地检查点只存有界恢复笔记 | 不叠第二个常驻压缩器/自动续跑链；逻辑上下文不等于扩大模型原生窗口 |
| 经验/检查点/记忆 | 区分自动元数据、语义笔记与长期偏好 | 仅当前作用域及持久化允许时写；明确不落盘则两个观察器均零派生写入；旧数据不授权 |
| 守卫/权限 | 宿主策略权威，按实际作用域验证违规拦截与正常允许 | 全局已有同一守卫时不再叠预设实例；有限预检不冒充完整安全边界 |
| 安装/发布 | 比较可信旧包、现役副本和新版本，最后独立实装 | 一套源＋派生元数据事务；保留定制、并发写入和恢复记录，不以版本号强覆 |
| 提示词/任务拆分 | 保留用户原意，查事实后只澄清影响路线的歧义；长/复杂任务沿现有VibeCoding文档 | 不把润色变授权，不重复问已给信息，不另开自评模型 |
| 并行操作 | 模型先判断独立性、读写边界和收益，再用宿主实际并行能力 | 共享接口/生成物/最终集成唯一写者；脏工作区保护；READY不等于已集成 |
| 验证/文档 | 模型按影响选择最低充分证据，失败保留首红 | 静态、fixture、实际 SDK、当前进程、真实外部服务分开；跳过不算通过 |

本说明适配 Qoder-Optimization v0.0.30 的按需目录、capability-advisor 路由与候选规划方法，以及 Codex 本地的任务/权限与独立验收边界。未移植 Qoder 的 hook、SQLite、模型或客户端配置，许可和版本关联见包根 SOURCES.md。冲突矩阵是检查与接线契约，不能保证未知第三方组合天然兼容；新组合仍须按实际能力验证。
