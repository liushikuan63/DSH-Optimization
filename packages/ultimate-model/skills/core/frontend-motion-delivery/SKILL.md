# 前端动效与可视化交付基线

**定位**：这是**交付门槛**，不是灵感建议。自研动效件（SVG 插画、海报、loading、演示动图）一律按产品级交付，**不因"只是 demo / 一次性预览"打折**。
**探针件例外**：一次性预览 / 不交付的**探针件**，按"**能跑、能动、不误导**"三项即可，并在汇报里标注它是探针件（不按产品级验收）。

来源：Qoder 侧 `rules/frontend.md`「动效与可视化交付基线」+ 记忆 `feedback-frontend-craft-bar` / `reference-svg-loop-animation-checks` / `reference-css-var-theme-trap` / `reference-svg-daynight-theme` / `feedback-expand-space-over-hide-content`（2026-09-18 与一份同类作品逐项对标后定的标准），2026-09-20 迁移为 DSH 技能。

## 一、交付清单（缺一项就不算交付完）

| # | 要求 | 可失败判据 |
|---|---|---|
| 1 | **暂停 / 播放控件** | 控件存在且 `aria-pressed` 随状态变化；点一下后 `getComputedStyle(目标).animationPlayState === 'paused'` |
| 2 | **`prefers-reduced-motion` 关动效** | 切到 reduce 后动效停止，且**与动效无关的控件仍可见可点**（见 §五.6） |
| 3 | **自适应宽 + 移动端断点** | 缩到 375px 宽不溢出、不重叠；`svg` 不写死 px 宽 |
| 4 | **复用而非复制** | 重复图形在 `<defs>` 定义一次、靠 `<use>` 实例化；同一份路径代码不应出现两遍 |
| 5 | **次级动画层** | 主体之外至少一层（眨眼 / 呼吸 / 影子同步 / 多元素错相）；同类多元素用不同 duration + `alternate-reverse` 错相 |
| 6 | **节奏有理由** | 匀速位移 `linear`、衰减飘散 `ease-out`；同场景多个周期**避免互为整数倍**（节奏锁死会看出循环） |
| 7 | **物理一致性（可算）** | 见 §二；差值 > 5% 即不合格 |
| 8 | **可移植性** | 字体不裸写系统字体名（`"Microsoft YaHei"` 到 macOS / Linux 必走样）；色值走 CSS 变量 |

**最常漏的是 1–3 与 5**（历史实测：能跑、也在动，但工程完成度整体落后一档，差的正是这几项）。

## 二、物理一致性判据（纯计算，静态看不出）

轮子驱动的场景必须满足：

```
2πr / 轮转周期  ≈  地面平移距离 / 平移周期        （±5% 内）
```

实测对照（同一份作品的两次迭代）：轮径 65 / 0.72s = 567px/s vs 路面 1120 / 2.3s = 487px/s → **快 16%，一直在打滑**；轮径 52 / 0.7s = 467px/s vs 虚线 200 / 0.43s = 465px/s → 差 0.4%，合格。

## 三、四类循环动画自检（每条都能失败）

| 检查 | 判据 |
|---|---|
| **旋转 / 缩放轴心** | `<g>` 用 `transform-box: view-box` + `transform-origin: <x>px <y>px`（viewBox 作者坐标），比 `fill-box` 猜包围盒中心可靠；嵌套变换各自取原点，不必换算 |
| **平铺层接缝** | 图层按周期 P 平铺、动画平移 -P 时须满足 `getBBox().x <= 0` 且 `bbox.x + width - P >= viewBox 宽`。实心层（山脊 / 护栏 / 路面）必须成立，否则循环后段**一侧整块消失**（实测：护栏铺到 1050、平移 450 后右侧 600–900 空了） |
| **虚线滚动** | `stroke-dashoffset` 终点必须是 `stroke-dasharray` **各段之和的整数倍**，否则每轮跳一格 |
| **平铺图形自身** | 重复图形起点与终点 y 相同（否则接缝台阶），并看**首尾切线斜率**是否连续——斜率翻转会在谷底留 V 形折角（用 `C` / `S` 控制点算方向向量：入 0.247 / 出 -0.38 即不连续） |

## 四、读值与取证的陷阱（均实测过）

- `getComputedStyle(el).strokeDasharray` 返回 `"46px, 34px"`，按 `\s+` 切分会得 NaN。
- `anim.effect.getKeyframes()` **拿不到** `strokeDashoffset`。要读关键帧声明原文：遍历 `document.styleSheets[].cssRules`，取 `type === CSSRule.KEYFRAMES_RULE`，再用正则从 `r.cssText` 取值。
- **"动画真在跑"的最小证据**：`document.getAnimations()` 的 running 计数 + 隔 ~260ms 两次采样 `getComputedStyle` 的 transform / dashoffset 必须**不同**。
- **`<use>` 影子树的两个假象陷阱**（2026-09-18 实测纠正）：
  1. `document.getAnimations()` **不枚举** `<use>` 影子树里的动画（实测某页 16 个动画恰好等于 light DOM 元素数，影子树目标数 0；`use.shadowRoot` 是闭合的、返回 null）。**影子树里的 CSS 动画其实是真生效的**，不能据此判"没在动"。
  2. `getBBox()` **不含**元素自身与祖先的 `transform`（`<g transform="translate(200,100)"><g class=spin>…` 的 bbox 仍是 `[0,-5,40,10]`）——它既验不出轴心也验不出旋转，别当判据。
- **可行手法：注入式放大标记**。往 `<svg>` append 一条 `<style>`，把目标动画放慢（`.spokes{animation-duration:9s !important}`）并把组内一条**不对称**的 path 染成醒目色，隔几秒两次截图对比：① 标记是否始终距某圆心等距（验轴心）② 角度是否变化（验在转）。
  **对称图形验不出角度**（8 辐条有 45° 对称性），必须挑组内**唯一的不对称元素**当标记。

## 五、主题切换（昼夜 / 局部换肤）

1. **`var()` 的静默坑（最高频）**：`var()` 在**声明所在的元素**上解析。`body { color: var(--ink) }` 在 body 处就把颜色算完，并作为**已计算值**被后代继承；后代再重定义 `--ink` 影响不到它 → 页眉页脚"切了主题文字不变色"，深色底上几乎不可读。
   **正确做法**：把 `color: var(--ink)` 声明在**重定义变量的那个容器**上（如 `.poster { color: var(--ink) }`），或每个用色元素各自声明。
   **判据**：切主题后用 `getComputedStyle(header).color` 量**计算值**，不靠截图猜。
2. **合成顺序**：环境美术 → `<rect class="veil">`（垂直渐变压暗，顶部更深）→ 夜里要保持明亮的东西画在 veil **之上**（月亮 / 星星 / 标题 / 灯光层）。切换主题就只是若干 `opacity` 的 0↔1，配 `transition: opacity .6s` 有平滑换场。
3. **主体单独调亮度**：主体组 `filter: brightness(.74)` + `transition: filter`，与环境解耦——环境压狠、主体轻压才有层次；整张一起变暗会糊成一片。
4. **光源重绘在 veil 之上**：头灯 / 尾灯在主体组里会被一起压暗，必须在夜光层重画一份亮芯 + 泛光 + 光锥 + 地面光斑。
5. **过渡起始值陷阱**：切换后**同一 tick** 读 `getComputedStyle().opacity` 只会拿到过渡的**起始值**（读到 0 不代表没生效）。要断言主题态就读 class / `aria-pressed`，或等过渡结束再读。
6. **a11y 收窄**：`@media (prefers-reduced-motion: reduce) { button { display: none } }` 会把**与动效无关的控件**（昼夜切换）一起藏掉。选择器必须收窄到具体控件（`#toggle`）。
7. 给元素加 CSS `filter` **不影响** `<use>` 影子树里的动画（实测轮辐仍在转、`getComputedStyle(.spokes).transform` 有真实转角），可以放心给主体组加。
8. **夜里才成立的元素**：白天不该出现的（如白天场景里的车灯光锥）别硬塞，用主题态控制显隐——既保物理正确又不浪费元素。

## 六、合并两版作品时的教训（实测）

不要按"我这版有、他那版没有"的清单无脑移植——**先验证该元素在对方配色与场景下读不读得出来**。实测：把自己的黄光前照灯光束搬进米黄海报，截图发现几乎不可见（只剩沙丘上一片淡雾），且白天场景本就不该有可见光锥，于是撤掉。

**判据：读不出来的元素等于死代码，宁可少一个**；"我有的元素"未必适合对方的 art direction。

## 七、一条必须纠正的过时认知

**SMIL 并没有被弃用**——Chrome 2015 只提过弃用意图、从未实施，各浏览器至今完整支持。**别拿"已废弃"当改用 CSS 的理由**（写进规则的技术论断必须查证，不把社区口口相传的过时结论当事实）。

改用 CSS `@keyframes` / WAAPI 的**真实**理由：SMIL 不参与 `prefers-reduced-motion`（要 JS `pauseAnimations()` 兜底）、无法与页面 `animation-play-state` 一起统一暂停。
**唯一例外**：要交付可单独复用的单体 `.svg` 资产时（CSS 写在 HTML `<head>` 里，抠出 SVG 就成静态图）；页面交付不能拿这个当借口。

## 八、布局：空间优先于隐藏

布局拥挤时**优先扩空间**（增加间距 / 尺寸），而不是减少显示数量或截断内容。核心信息（服务器详情、指标图表）**永远不可为辅助展示让路**——辅助展示可以缩小或调整，核心信息必须完整清晰。

**判据**：调整后核心信息块未被辅助展示挤压（给核心块 `flex-shrink: 0` 之类的保护）；确实要分页 / 折叠 / 限数时，**先给可回退的默认值并在汇报里点明**（选了哪种、怎么改回来），只有**会删掉或藏起用户已产生数据**时才先征得同意。
（实测来源：拓扑卡片扩到 600px 把服务器信息卡挤到 2px；用户原话"总览的核心信息不要丢啊，拓扑只是展示"。）
