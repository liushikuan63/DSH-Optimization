# 验证后再断言

## 自适应闭环与按需自测

排查、实现和交付共用[自适应证据闭环](references/task-selftest.md)：先按任务和风险分流，选择能区分竞争假设的低成本探针，再按证据跳转、回退或结束。六项检查点不是固定流水线；没有缺陷不修复，只读任务不制造修改，简单问答不强行填表。

需要核对多项证据时，使用[最小账本](templates/task-evidence.json)和只读一致性检查器；缺证据保留未验证，不能用自填账本证明实载、权限或模型能力。细节与方法来源只放上述按需参考，不常驻展开。

## 先确定验什么

- 读取当前项目规则、入口和锁文件，确认本轮影响面、真实测试命令及完成判据。
- 不假定“没有测试/CI”，也不把某个旧仓的 Maven、端口、URL、语言列表或发布方式推广到所有项目。
- 每条结论都要能被错误实现反驳；没有证据写“未验证＋原因”，不写“应该没问题”。
- “源码改了/文件存在/配置可解析”只证明静态状态，不证明被装载、调用或生效。

## 按影响面选择证据

| 改动 | 本轮最低证据 |
| --- | --- |
| 一次性小操作 | 一条可失败的退出码/读数，精确对应目标 |
| 实现或修复 | 受影响正反测试；构建/类型检查适用时必须报告真实退出码 |
| 服务/接口 | 本轮产物与进程归属、成功请求、负向对照、响应内容与类型 |
| 界面/交互 | 实际运行、完整用户路径、负向用例、截图；见 verify-ui-in-browser |
| 插件/预设/MCP | 静态配置＋真实宿主装载＋工具/协议关键路径，缺哪层就单列 |
| 安装包/发布产物 | 最终产物晚于最后修改，运行那份产物并验关键路径 |

## 防止假绿

- 测试跳过不算通过；依赖在运行却不可用必须失败。批量测试不应第一项失败后让后续项变成“未跑的绿灯”。
- 管道最后一个命令的0不等于编译/测试成功；保存原始命令退出码，不用旧产物掩盖本轮失败。
- mock 的方法、路径/base URL前缀、数据形状对齐真实上游；mock通过与真实服务通过分别报告。
- 服务确认监听端口/进程属于本轮，不能杀别人的进程或把别的进程响应当自己的成果。
- SPA的200可能只是HTML fallback。真实API与编造路径对比状态、content-type及响应形状，不硬编码所有负向都应404。
- 计数先列会增删对象的操作；时间用可控时钟或充分余量，不能靠机器恰好够快。
- 修复先留可复现坏读数/失败用例，再复跑变绿；临时破坏验证仅限隔离夹具，不能向生产植入违规。

## 交付前边界

- 发布/推送/部署需真实授权与项目规定的完整验收；测试通过本身不构成授权。
- 依赖凭据、外部权限、重启或不可得GUI的路径保持未验证，不以静态检查代替。
- 本机历史项目适配可放 references/；只有当前工程匹配且重新核对现场后才使用。
- 独立验收与实现者自测分开；未做独立验收不要用“全量验收”措辞。
- 安装、升级或技能分层同时改源文件与索引/可读目录时，按需读[派生元数据事务验收](references/derived-metadata-transactions.md)，验证同快照、失败恢复与并发写入保留。

## 汇报

明确分为：已落地并验证（命令/退出码/覆盖）／已改但运行时待验证（具体缺口）／未做。
只有出现旧产物、错进程、伪退出码等可疑信号才补有针对性的复验，不为凑证据循环查询。
