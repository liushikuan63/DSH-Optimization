# 派生元数据与源文件的一致性

适用于技能安装、升级和 core/library 迁移。正文修改不生成派生文件时，无需扩成安装工程。

1. 在改动前完整校验元数据。机器索引与可读目录从同一次收集产生，记录最终安装路径；不能在移动完一半后才发现坏 frontmatter。
2. 记录将触及文件的预像哈希和对象身份；暂存到同卷自有目录。提交前重查，独占创建新目标，不用覆盖恢复消灭并发改动。多文件顺序发布不等于操作系统原子事务。
3. 失败时保留恢复记录，恢复源文件、索引、可读目录和启用状态。撤销新对象先移入自有 stage，再核对移入对象的身份与哈希；匹配才删除，不匹配则独占还原并保留恢复目录。检查后直接 unlink 仍有竞态。
4. 验收包括：正常后重新收集一致；可读目录发布后注入故障完整回退；所有权检查与删除之间替换对象仍保留并发字节；旧 builder 缺 API 拒绝且不碰现役索引。

只在隔离、自有测试树注入故障。真实 home、私有状态、权限和外部发布沿当前任务授权，恢复失败不能冒称成功。只读 preview 不打开写连接、不迁移或修复源 WAL，也不调用有副作用的重建。
