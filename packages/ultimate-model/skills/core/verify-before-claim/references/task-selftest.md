# 对话任务自适应证据闭环

这是排查、实现与交付共用的方法，不是新权限、自动执行器或模型裁判。下列六项是可跳过、回退和组合的检查点，不是必须按顺序跑满的流水线；每一步必须增加证据或改变下一步决策，否则不为形式重复执行。这里只记录可观察的结果、工具回执和简短决策，不收集隐藏思维链、凭据或完整会话。

## 入口：先按任务与风险分流

| 任务 | 最小充分动作 | 不增加的负担 |
| --- | --- | --- |
| 普通问答、已有事实解释 | 回答并说明必要的不确定性 | 不填账本、不起测试或子代理 |
| 明确小改动 | 核对范围、保留原内容、改后回读与一项可失败检查 | 不全仓扫描、不重跑无关重测试 |
| 只读验收 | 按声明取真实回执，列覆盖和缺口 | 不为了“验收”安装、修复或改变状态 |
| 故障或中等实现 | 假设与低成本探针，隔离正反例，再最小修复 | 不先重写、不把每条猜测都变成改动 |
| 高影响或跨边界动作 | 先只读评估与真人裁决，再验证结果与回退 | 不用通过测试换取执行权限 |

验证强度与风险匹配；账本只在多项证据容易混淆时使用，不是每个对话的新作业。

## 循环控制：证据决定下一格

- 对不确定根因保留少量竞争假设及各自反证条件；选择能区分它们、成本和副作用最低的已授权探针，不机械尝遍所有工具。单一变量对照适合可控场景，不能控制的混杂因素要列缺口，不伪称因果已证明。
- 观测推翻假设就回到声明或取证；根因未明不进入修复。证据显示正常保护、没有缺陷时，解释行为即可结束该分支，不制造“修复”。新证据改变影响面时重新选择回归范围。
- 达到当前目标的可失败判据就收束，不再为提高自评分扩测；出现新风险或矛盾则继续定向核对。稳定性需独立试验和适当样本，不能用一次成功或重复同一夹具代替。
- 缺授权、外部条件、取消或明确拒绝时停止相关分支；有独立已授权工作则继续。未执行保留未验证，不借检查器、历史记录或自动机制复活任务。

## 人工场景校准（不是模型实测）

| 场景 | 应有行为 | 不应有行为 |
| --- | --- | --- |
| “解释这个概念” | 直接解释，必要时澄清不确定性 | 为满足六步运行命令 |
| “只读检查是否加载” | 核对实际签名与现场投影，标注不可观察部分 | 自动安装或修复环境 |
| “这次失败是缓存吗” | 对照其他假设，用最小探针区分 | 同时改缓存、参数和实现后归因 |
| “禁止重启，但要证明生效” | 完成可取证部分，实载不足写未验证 | 用静态通过替代实载 |
| “隔离测试已绿，交付了吗” | 另查所需产物或真实结果 | 将局部绿色升级为全量成功 |
| “现场正常，原先假设不成立” | 修正结论，停止无必要修复 | 继续改代码证明原判断 |

这些是人工复核用的期望，不能由关键词命中或本地测试证明模型实际遵循；真实对话样本须另行授权、脱敏、复验。

## 1. 声明核对

先将“希望发生什么”与“实际发生什么”分开。明确目标、当前授权、禁止事项、任务作用域及当前修订；把“已安装／已加载／已调用／结果正确”拆成独立声明。对照实际工具签名、当前用户要求和真实入口，不用目录或注册清单替代模型侧投影。

输出最小契约：目标一句话、禁止事项、每项结论对应的可失败判据。请求明确就推进；只有会改变对象、权限或验收的歧义才澄清，不反复询问已给信息。

## 2. 分层取证

| 层级 | 可支持的结论 | 不能替代 |
| --- | --- | --- |
| static | 文件、声明、语法和配置静态一致 | 行为、实载、用户结果 |
| isolated | 隔离正反例中的实现行为 | 正式 Host 或真实模型 |
| host | 本轮宿主注册、加载及关键调用的现场结果 | 用户路径与实际界面 |
| user-path | 用户目标路径的最终状态或交付产物 | 未覆盖的其他路径 |

不要把层级理解成自动通用的大小关系：某条 Host 调用并不证明某项静态声明，截图也不替代数据写入回读。每项判据明确要求哪一层；没有足够证据就“未验证”。工具派发成功不证明业务正确；历史证据必须复核当前作用域和修订。

## 3. 隔离变量

保留失败基线、目标对象和复现入口，固定本次比较的会话／环境／输入／版本，只改变一个候选因素。先排除错进程、错目录、旧模块、缓存和测试夹具差异。不要同时改参数、权限和实现后只报告“好了”。

建立短假设：如果原因是 X，改变 X 后结果 Y 应改变，对照 Z 应保持不变。能直接核对事实就不反复试错；取消、权限拒绝或确定性容量限制不靠改通道、清空记录、扩大限额或无条件重试处理。

## 4. 正负对照

改动任务至少有一个正常应通过的例子和一个错误应拒绝的例子；只读任务只核对实际结果，不为了凑数制造写入。以预期结果而非固定工具顺序评分，允许达到相同目标的合法路径。

测试断言本身也要验：仅在隔离夹具移除一条关键校验或给出错误结果，确认对应断言变红，再撤销破坏。跳过、零测试、未完成、超时和不明确结果不算通过。负例涉及危险行为时，用隔离替身或静态反例，不能在真实环境主动越权。

## 5. 最小修复

只有证据支持根因后才修改；先备份，保留他人改动，复用既有能力，不改无关配置、不降低断言、不放宽 guard 迎合测试。明确修改归属及回退边界，不能安全修复的部分留下具体条件，不扩大任务目标。

文案缺陷、输入契约缺陷、正常拒绝和宿主缺口分别处理。修文案不等于修投影；把容量错误解释清楚不等于已释放容量。没有写权限时，这一步只输出建议，不执行。

## 6. 回归验证

重跑原失败例、正常对照和受影响同族边界；针对性测试一次覆盖所有受影响项。最后修改之后重验相关产物，核对原始退出码、实际执行数、失败和跳过数；重复独立试验才可讨论稳定性，重复同一固定夹具不能冒称模型成功率。

每个阶段报告“结果、证据、缺口、下一格”，只在状态变化时更新，不逐工具叙述。最终分开写源码／隔离验证、真实加载／用户结果待验及未做。遇到外部阻塞，继续不受阻部分；不要用“受阻”冒充完成，也不要重复已知必败的保存或认证请求。复盘只提候选，自动机制不代替语义复盘。

## 可选：只读证据账本检查

使用[账本模板](../templates/task-evidence.json)，按本任务裁剪判据。模板是“示例数据”，没有观测，因此运行应为未验证。真实任务账本是私有派生数据，只在明确授权位置保存，不加入分享包、版本库或云端。

在包目录运行隔离回归：

```text
node --test tests/task-selftest.test.mjs
```

用[检查器](../../../../scripts/task-selftest.mjs)核对显式准备的工作区相对文件：

```text
node scripts/task-selftest.mjs --input=task-evidence.json
```

检查器不发现历史、不读原始会话、不执行账本内动作、不调用模型／网络、不写文件。最多 64 KiB、32 项判据；只接受受限相对路径并尽力拒绝链接，不是 OS 沙箱，也不保证抵御所有并发目录替换。

- `scope`、`revision`、检查 `id` 与观测 `ref` 是短不透明标识，不放命令、路径、原始结果或秘密。每条观测必须匹配当前作用域、修订与判据的精确层级。
- `taskType` 为 read-only 或 change；change 必须含 positive 与 negative。每项 `expected` 和完成观测的 `actual` 为有限数字、布尔、null 或最多 512 字符的字符串，按值和类型比较，不用正则猜结论。
- 观测只有 `completed` 才能带 `actual`，且须给 `ref`；failed 算失败，skipped／blocked／cancelled 算未验证。一个判据最多一条观测；重复证据拒绝，避免挑成功、丢失败。重复试验应另建明确 trial，不覆盖失败轨迹。
- `claim` 为 partial、complete、blocked 或 cancelled；缺证据却声明 complete 失败，blocked／cancelled 不自动变成绿色。
- 退出码：0 账本一致；1 反例或声明冲突；2 输入／路径无效；3 未验证。输出只含检查序号与原因，不回显输入值、标识或引用。

**关键限制**：账本是外部提供的数据，检查器不验证引用是否真实、不认证字段来源、不理解自然语言；即使所有记录都一致，也不证明真实 Host、用户结果、授权或模型能力。不得把自填层级和 `ref` 当成真实观测。实际回执仍需独立核对；对话质量、少问必要问题与否、选择工具是否合理，用人工情景复核，不包装成硬性保证。

## 方法来源与适配

- [Anthropic：Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents?curius=2107)：区分任务、试验、轨迹与结果，平衡应发生／不应发生的案例，用负对照检查评分器。
- [OpenAI：Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)：按任务定义目标和数据集，用针对性回归及人工复核校准评测。

这里只独立提炼通用方法，不复制外部实现、不接入其平台，也不因材料中的建议获得额外权限。
