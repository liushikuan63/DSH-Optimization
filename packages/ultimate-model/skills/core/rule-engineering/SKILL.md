# 规则工程

## 分层而非堆叠

| 内容 | 合适载体 |
| --- | --- |
| 高频跨任务纪律、安全/授权边界 | 短的用户级/项目级规则 |
| 领域流程、脚本用法、案例 | 按需技能与references |
| 可判定的安全约束 | 宿主支持的单调guard、lint、CI |
| 广搜与隔离子任务 | 独立读域/写域代理 |
| 一次性环境事实 | 经核验的状态文档或记忆 |

- 先服从系统/开发者契约与用户具体授权；具体项目规则不是扩大权限的机制。
- “机制胜过文字”用于核对现场，不代表缺陷机制可提供授权；发现fail-open要修，不把漏拦当允许。
- 不宣称提示词或hook能保证100%安全。需要机器强制时先确认API语义、作用域、异常路径与执行顺序。

## 单一真源

- 同一事实只维护一个源，其他位置引用、提取或生成；不让AGENTS与reminder各维护一份近似清单。
- 多个必需副本保留可失败的漂移检查；配置目录与激活器要从同一配置派生。
- 同源链接只解决重复，不证明内容正确；检查链接目标与内容约束都能失败。
- 稳定文本有利于前缀复用，但不能为缓存稳定拒绝修正过时事实；不在常驻段加入时间戳/随机数。

## 注意力预算

- 同时量行数、UTF-8字节与重复段落；少行不等于短，不把文本减少率冒充实际token/费用减少率。
- 常驻只留纪律与地图，项目版本故障、端口和长案例外置；精简前后对照独有能力去向。
- 描述清楚触发条件，正文在相关任务才读取。当前目录没列出不等于能力不存在，给出检索路由。
- 不照抄历史固定技能总数、provider名单、版本或工具参数；从现场/公开schema确认。

## 运行机制

- 写插件/预设前加载对应Cordis技能并查Inspect。Inspect查询是只读反射，不是业务Service调用通道。
- 安全红线优先用tools.guard等单调拒绝机制；普通pre-execute waterfall可被前置listener短路，不能当同等保障。
- 注册需要声明依赖并绑定disposer；预设级能力不能泄漏到未选择它的模式。
- 命令hook的退出码、stdin、超时、scope与fail-open语义需按当前版本复验；旧README和旧心跳不证明当前在线。
- 启动体检只诊断，不静默改依赖、迁移目录或重启服务。用户取消后不得靠自动续跑复活任务。

## 验证与收尾

- 先静态配置与资源闭包，再正反回归，最后真实宿主装载/触发；每层证据分开报告。
- 测守卫：危险项必须拒绝、正常对照必须放行、判定异常不悄悄变许可；测试只在隔离夹具。
- 测隔离：A会话条目不进入B，B修改不能刷新A停滞额度；未声明scope不是全局授权。
- 配置改了但旧会话持有旧组合、JS仍在内存时，明确写运行时待验证，不擅自重启。
- 先备份并保留失败轨迹；收尾给改动、命令/退出码、缺口与下一格，不用“文件存在”充当生效证据。
