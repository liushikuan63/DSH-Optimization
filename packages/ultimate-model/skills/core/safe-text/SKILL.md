# 文本与传参的字符安全

> 来源：Qoder rules/safe-text.md + 参考包 skills/safe-text-editing/SKILL.md（2026-10-13 移植）。

**共同症状是"不报错只出错"**：命令退出码 0、脚本无语法错，但字符被改写、替换没命中、或改的不是你以为的那一处。

## 一、要写的文本 / 多行脚本，先落成文件再执行

- 用编辑工具直接写文件，或用**带引号的 heredoc**（`<<'EOF'`）——引号让 shell 不做替换。
- **禁止**在 `node -e "…"`、`bash -c "…"` 里出现反引号 / `$` / `\`；脚本落成 `.cjs` / `.js` 再 `node <file>`。
- 被 `huge-output-guard` 之类的守卫拦下时**改写法，不要绕**——它的判据是踩过的坑。

## 二、先判断"是谁吃掉了字符"

| 现象 | 根因 → 正确写法 |
|---|---|
| 双引号里的反引号或 `$` 被当命令执行，文本变形 | 双引号里 shell 先做命令替换与变量展开 → 落成文件，或用 `<<'EOF'` |
| 替换后**体积暴涨**、同一节出现多次 | 替换串里的 `$` 有特殊含义（`$&` / `$1` / `$` 紧跟反引号等），JS `String.replace` 与 Python `re.sub` 都中招（实测 47k 文档被一次放大到 128k）→ 用**函数式替换**：`s.replace(锚点, () => 文本)` / `re.sub(锚点, lambda m: 文本, s)`，替换后断言「目标节只出现 1 次 + 体积增幅有界」 |
| 替换脚本"跑成功了但没改到" | 匹配串是**手抄**的（转义层数 / 全角半角引号 / 尾随空格 / CRLF 与文件不一致）→ **从文件里程序化提取**（读那一行，用它构造替换串） |
| 脚本语法通不过 / 数组少一个元素 | 拼接替换文本时把分隔符（`,`、`],`）吃掉了——典型是"整条替换"只换了前半段 → 替换后立刻 `node --check`；构造长字符串时**在末尾显式带分隔符**，并断言"替换条数 = N" |
| 命令明明失败，脚本却继续 | `cmd \| tail` 的退出码是 `tail` 的 → `cmd > x.log 2>&1; echo $?`，或用 `${PIPESTATUS[0]}` |
| Node 打不开 `/tmp/x`（被当成盘根下的 tmp） | MSYS 的 `/tmp` 与 Node 路径口径不同 → 用 `os.tmpdir()` / `%TEMP%` 全路径 |
| 多行脚本改了一半又报错，文件处于半改状态 | 没落盘就执行、没有存档点 → 先备份；大文件分批改并**每批回读** |

## 三、编辑动作本身的三条规矩

1. **局部替换优先于整文件覆盖**：定点替换天然带"匹配失败即报错"的保护；整覆盖没有任何保护，写错就是把文件擦了（必须备份 + 回读）。
2. **替换文本先看字节再看语义**：涉及反斜杠、引号、制表符、中文标点时，先看清真实字节再构造替换串。
3. **同一文件的多处修改一次构造、一次写盘、一次校验**——分多次小改容易留下半成品，且并行会话可能在你两次读之间改了它。

## 四、写完必跑的回读校验（判据要能失败）

- 语法类：`.js` → `node --check`；`.sh` → `bash -n`；`.json` / XML → 解析一次。
- 内容类：**「新片段在」与「旧片段不在」两条都要断言**——只查前者会被残留内容蒙混。
- **编码照抄目标端**：`.cmd` / `.bat` 必须 **GBK + CRLF**（完整"改 / 验 / 发"链见技能 `verify-windows-cmd-tool`；DSH 未装该技能时按 GBK+CRLF 手工核 + 逐字节比对）；
  `git commit` 中文用 **`-F <消息文件>`**（内联 `-m` 过不了编码层，会存成乱码）；面向 Windows PowerShell 5.1 的中文 .ps1 需要 UTF-8 BOM，现代 pwsh/技能/JS 默认 UTF-8 无 BOM＋LF，保留既有目标编码；
  Git Bash（MSYS）把裸露 `/x` 当路径改写 → 加 **`MSYS_NO_PATHCONV=1`**，或把值写进配置文件由程序读。
- 拿到的必须是**退出码或字节比对**，不是"看起来对了"。

## 五、边界与反模式

- 本技能只管**文本与传参**：`.cmd` 工具的整套"改 / 验 / 发"（真机点选、截图、SendInput）走技能 `verify-windows-cmd-tool`（DSH 未装该技能时按 GBK+CRLF 手工核 + 逐字节比对）；纯文本内容校对走文档类技能。
- **别为了"让检查通过"绕过守卫**（`huge-output-guard` / `edit-guard`）：它们的判据都是踩过的坑，被拦就改写法。
- **ps 5.1 的 `Set-Content -Encoding UTF8` 会写 BOM，且内嵌换行被改写成 CRLF**（实测：ps 5.1.26100，`Set-Content` 写出的文件 BOM=True / CRLF=1）。技能与脚本类文本要求**无 BOM + LF** → 用编辑工具写，或 `[System.IO.File]::WriteAllText($p, $s, (New-Object System.Text.UTF8Encoding($false)))`。
- **涉及中文的跨机打包 / 提交，先确认目标端期望的编码**再决定转换方向——方向猜错＝把乱码换个地方。
- **改完别只看自己的改动**：同批还动过别的文件时，回读要覆盖**全部**被改文件，避免半成品留下。
