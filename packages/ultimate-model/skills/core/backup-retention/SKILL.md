# 备份保留策略（可选历史策略）

先确认当前用户采用本保留策略，并通过实际包目录定位脚本；自动清理涉及已有备份删除，必须符合当前任务授权。`<Addon包根>` 是可选 addons/Ultimate-Model 的绝对路径，Base 本地记忆运行包不附带该执行器。

> 用户原话：「同文件备份最多存在三份；下次更新新文件创建备份时，原有超过七天的备份，也进行删除」

## 一、三条规则

| # | 规则 | 判据 |
|---|---|---|
| ① | **同源最多 3 份** | 同一源文件的备份按创建时间倒序，第 4 份起删 |
| ② | **超 7 天即删** | 每次创建新备份时，顺带删除该源文件**创建时间早于 7 天前**的备份 |
| ③ | **最近 1 份永不删**（兜底） | 即使已超 7 天也不删——否则"唯一且已旧"的回滚点会被策略吃掉，那是自断退路而非控制膨胀 |

## 二、机制：`<Addon包根>/scripts/backup-file.ps1`

```powershell
# 建备份 + 自动清理（日常用这条）
pwsh -NoProfile -File "<Addon包根>/scripts/backup-file.ps1" -Path <文件> [-Reason <标记>]

# 只清理、不建备份（单文件或整目录递归）
pwsh -NoProfile -File "<Addon包根>/scripts/backup-file.ps1" -Path <文件或目录> -Sweep

# 先看会删什么（永不真删）
pwsh -NoProfile -File "<Addon包根>/scripts/backup-file.ps1" -Path <文件或目录> -Sweep -DryRun
```

- 命名：`<源文件名>.bak-<标记>-<yyyyMMdd-HHmmss>-<GUID>`（无标记则 `<源文件名>.bak-<yyyyMMdd-HHmmss>-<GUID>`）
- 退出码：`0` 完成或只读预演；`1` 复制、删除或迁移失败；`2` 参数错、目标不存在或不支持的路径。删除成功才计数，失败不会伪报完成。
- 同秒重复备份使用独立 GUID 并禁止覆盖。Reason 仅支持最多 64 个字母、数字、汉字、下划线或连字符；当前仅支持 Windows 盘符路径，UNC 在写入前拒绝。
- 清理只处理完整后缀可识别的本源备份，支持旧日期名与新 GUID 名；前缀相似的其他源、未知或歧义旧文件保留。最多份数仅针对可确认归属的受支持备份，源名含 .bak- 时使用显式单文件检查。
- -Migrate 会先快照候选并排除 BackupRoot 内部文件；目标同名时保留源与目标并返回失败。迁移和清理沿当前任务授权，先用 -DryRun 核对；输出根不再被迁入自身。
- **判龄与排序一律用备份自身的 `CreationTime`**，不用 `LastWriteTime`——`Copy-Item` 会保留源文件的修改时间，用后者会删错对象（2026-10-14 实测踩到，见 §四 反例 2）

## 三、何时用

- **改已有文件前**：跑脚本建备份（替代手写 `Copy-Item`），保留策略自动生效
- **发现备份堆积**：先 `-Sweep -DryRun` 看影响面，确认后去掉 `-DryRun`
- **已被版本库纳管且历史可回退的文件**：在没有更具体备份要求时可免（对应目标机 `AGENTS.md` §一.5 的备份条款）；当前用户明确要求逐文件备份时不得豁免。仅备份当前授权源文件，不借机批量扫描或清理其他文件。

## 四、判据与三类反例

**判据**：清理后，任一源文件的备份满足「份数 ≤ 3」且「除最近 1 份外，创建时间都在 7 天内」。

- **反例 1（扫不到）**：手工起的名字不匹配 `<源文件名>.bak-*`（如 `backup-AGENTS.md`）⇒ 策略扫不到、**永不清理**，会变成永久垃圾
- **反例 2（删错对象）**：用 `LastWriteTime` 判龄 —— 刚从很老的文件复制出来的备份会被立刻判"超 7 天"删掉（`Copy-Item` 保留 mtime）
- **反例 3（策略空转）**：把 `-DryRun` 当默认不执行；或反过来，**批量删除前跳过 `-DryRun`**，影响面未知就开删
