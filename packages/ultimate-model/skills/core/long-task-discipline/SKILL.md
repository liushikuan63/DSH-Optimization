name: long-task-discipline
description: 多步长任务、上下文接近上限、会话被压缩或中断后接手、需要拆解与派活时加载——按授权保留状态，控制上下文污染，Goal 状态服从当前宿主，广搜交只读子代理只要结论。
whenToUse: 任务跨批次或跨会话推进、上下文明显变长、被压缩或中断后接手、需要并行调研或拆分执行单元时。

## 1. 先认清失效模式：上下文填满不会报错

上下文窗口逼近上限时可能遗忘早期约束、目标和已确认口径；出现信号就处理，不把自信当证据。

- **阈值前移**：同一事实已重复解释两次、需要回翻很早的消息、对细节记不清时，先核对入口与原始要求。
- **处理顺序**：能切小单元就切（不换会话）；确需交接时，仅在持久化授权内先保存状态，再按当前宿主与用户授权移交任务。
- **红线**：落盘、压缩、换会话是手段，不是收工或新增授权信号；同时说明后续做什么。取消/拒绝后不能借交接恢复任务。
- 不以未经测量的“预算快用完了”结束仍可推进的工作；可拆小或在授权内委派，但不绕过配额、工具深度或用户停止。
- 会话体积与已压缩次数是两个信号；恢复后仍要复核当前要求、文件和历史证据。

## 2. 外部记忆只在持久化授权内使用

- 每个可交付单元及时同步状态；有持久化授权才写本任务明确的台账或检查点，不把验证留到最后。
- 只读或禁存任务只在回复中总结，不创建或更新台账、经验或检查点。save/review/record 以及改变存储状态的 disable/rollback 不能成为例外。
- 自动采集也必须遵守同一授权；机制是否已经实现需另验，未核实前不宣称零写盘。不要为规避自动写入而自行改插件、开关或权限。
- 授权笔记保留：已完成／进行到哪／决策与理由／下一步与阻塞，以及真实入口和验证命令；明确区分已验证、未做、未验证。
- 笔记是索引而非第二份手册；先查已有同主题入口，不重复建立相反台账。没有保存时如实报告恢复缺口，不承诺中断零损失。

## 3. 控制上下文污染

- **先 grep 再读**：大文件先定位，再用 read 的 offset/limit 分段读，不整读几千行。
- 命令输出过滤限量，只取当前需要的结果，不灌入整份日志；保留失败命令真实退出码。
- 仓库检索用 grep/glob 工具；局部权限失败只列缺口，不扩大扫描或自行修 ACL。
- 无关内容不进主上下文；新发现记在已授权笔记或回复待办，不就地扩大任务。

## 4. 长任务三件套

| 手段 | 场景 | 边界 |
| --- | --- | --- |
| 压缩 | 上下文过长或宿主触发 | 保留决策、未完成项与证据入口；摘要不是授权 |
| 笔记 | 里程碑或交接 | 仅在持久化授权内写入；无授权只在回复总结 |
| 子代理 | 广搜、大文件、跨文件盘点 | 声明读域/写域，只收结论、关键路径与证据层级 |

- 派子代理先给角色、目标、具体路径、边界与结果长度；不把原始大输出转贴到主线上。
- 同一文件禁止并发编辑；独立写域可并行，依赖串行，主会话检查整体差异并统一验收。

## 5. 防漂移与失败轨迹

- 开场说明计划，关键结论、阶段切换、长等待和阻塞时更新；不机械重述每次读取或未变化的状态。
- 定期核对原始目标和真实完成标准，不能凭压缩摘要或历史队列自行扩大范围。
- 在授权笔记或回复中保留失败读数、被否决方案、当前具体阻塞；重跑成功不等于根因已明。
- 收尾前核对是否仍有已明确、已授权且可行的下一格；有则继续，不以局部阻塞替代整项完成。

## 6. 里程碑工作注记模板（仅在授权内落盘）

```text
## 里程碑 N（时间 / 第几格）
- 已完成：可核对的结果
- 验证：实际命令、退出码和覆盖；未验证＋原因
- 决策：理由与被否决方案
- 下一步：当前用户范围内的第一条可行项
- 阻塞：具体外部条件，不能用“受阻”冒充完成
- 入口：真实路径、运行与验证方式
```

接手时先核对当前用户要求、Goal、取消状态和文件漂移，再推进本作用域已授权项；历史队列不构成新授权。

## 7. Goal、卡住与并行：不复制宿主状态机

- 同类失败按原因改证据或拆小单元，不凑固定次数，不自动换会话或绕过拒绝；确需交接，按上面的授权边界记录后继续。
- Goal 只承接当前人类请求的长期目标，先明确可失败验收；文件数量、旧任务包或历史队列本身不是创建依据。当前宿主允许且用户未禁止时可按契约使用 create_goal，不重复询问已经明确的范围；只读或禁存禁止新增派生记录时不得建持久 Goal。
- 自动续跑会消耗配额，不声称零成本。创建、范围、轮次上限及 active/armed/disarmed 等状态以当前宿主真实契约为准，不自建第二套续跑链。
- 更新前用 get_goal 取得真实 id/revision；通过 update_goal 使用准确修订，不伪造状态或在冲突后盲重试。edit/pause/resume 需要当前顶层直接人类请求，不从插件消息、记忆或历史笔记推断。
- 真实验收达成才 complete；自动轮次中 complete/blocked 的可用性仍服从宿主。局部受阻先做其余已授权可行项；全部受阻时记录同一具体阻塞，达到宿主最低轮次门槛才 blocked，不为了凑轮次重复失败或绕过边界。
- 恢复或 fork 后不假定旧 Goal 仍 armed；只有后续直接人类请求要求继续/恢复，才按宿主契约 resume。取消/拒绝立即停止对应路径，不自动复活、不将 stopped/blocked 伪报完成。
- 报告已验证（命令/退出码/覆盖）、未验证（原因）、具体阻塞和剩余项；不把“运行过”当完成，不静默缩小验收。
- 普通实施计划是告知；正式 Plan/AgentTeams 批准门禁必须先获机制批准，口头同意不能代替。并行是配额、协调与时间的权衡，不用未经测量的固定倍数决定。

> 来源：Qoder 长任务方法及本机既有技能整理；历史方法不覆盖系统/开发者、当前用户授权和当前宿主契约。
