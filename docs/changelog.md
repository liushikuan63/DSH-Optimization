## 维护者发布流程

先读项目约定、检查工作区和改动归属；只提交明确文件，不将个人Home、账号、模型配置、私有规则、经验库、会话journal、启动token或临时验收辅助放入公开树。

1. 完成相关实现、能暴露问题的反例、适当回归及文档。按验证层记录实际命令、退出码、失败/跳过和未验边界；本机目录变更不能替代实体包实装。
2. 对齐VERSION、README下载版本、更新记录和脱敏摘要，固定源码提交。插件变更另更新插件版本/清单，并重新验收其最终ZIP；相同旧字节可通过精确比较关联已有证据。
3. 从干净固定提交新clone，在仓库外的新目录构建：

   ```text
   python scripts/build-release.py --output-dir <仓库外的新目录>
   ```

   构建器只用公开白名单并检查链接/状态目录/物化源；生成完整ZIP、独立插件ZIP和各自SHA256侧车。同名输出存在就拒绝，不覆盖旧版。

4. 由独立验收者解包，核对CRC、路径、链接、大小写冲突、成员集合、清单、源码对应与是否含私有状态。涉及安装行为时在新Home/profile做官方实装；源码或构建成功不能替代它。
5. 发布固定提交的tag和四个明确命名的资产；现有资产不替换，不把GitHub自动源码快照当作已验安装包。当前版本按预发布交付，范围写在Release说明中。
6. 读取远端main/tag，重新下载四个资产，与本地固定文件逐字节及SHA256比较；保留源提交、包哈希、环境、验收者及本地/远端回执。上传成功本身不是交付验收。

当前构建不需要下载依赖或联网，也没有新增CI工作流。发布GitHub和真实模型请求分别需要适用授权；不得从排队、计划、工具返回或等待超时推导授权。
