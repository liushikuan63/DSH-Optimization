# DSH-Optimization 1.1.0 验收

[English](en/acceptance-1.1.0.md) · 简体中文

本版组件为 Ultimate-Model **1.5.0**，预设 ID 仍为 `ultimate-model`。清单中的 DSH 版本约束为 `*`；每个宿主仍须提供旧式工具呈现接口或新版作用域执行器。未知接口会给出加载错误，不能用通配符推断兼容。

| 验证层 | 范围与判据 |
| --- | --- |
| 源码与自动测试 | 组件测试覆盖两条分页接口、激活结算、会话隔离、宿主模块来源和安装边界。根级测试另核对规则安装、元数据事务与修复工具。 |
| 真实安装宿主 | Windows x64 上已安装的 DSH NEXT 2.0.24-next / Harness 0.2.2-rc.5；在临时 Home/profile 中用官方管理器链接安装，从管理器读回版本、来源和启用状态。标准与 Ultimate 可新建；移除后再次启动，确认 Ultimate 不在列表，标准仍可用。 |
| 原生分页 | 本机回环模拟供应商，PPT 与 MiniMax 工具为测试声明。检查首轮隐藏两族且保留激活指引、同批调用拒绝、结算后下一请求可用、未知族拒绝和第二个会话隔离。计数由测试工具清单估算，不能代表实际用户配置或计费。 |
| 其他宿主与用户状态 | 旧接口由回归覆盖；实装模块接口另外核对了 0.2.2-rc.5 与锁定的 0.2.3-alpha.2。未对所有旧版、未来版、PTC 真实供应商请求或其他平台做实体包实测。未读取真实账号、会话、凭据，未运行生产 profile 或付费模型。 |

正式发行附两份 ZIP、各自 SHA256、包含源码提交的构建 JSON，以及从最终 ZIP 独立提取后出具的实装验收 JSON。以这些附件上的提交和摘要关联实体包与测试结果。

新环境参考[首次安装](getting-started.md)；已有定制用[部署与恢复](deployment.md)核查当前目录和同 ID 的配置覆盖。[1.0.0 历史验收](acceptance.md)及[历史模型记录](real-model-validation.md)只归属各自的原版产物。
