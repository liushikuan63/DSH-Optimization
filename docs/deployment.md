# 部署、升级与恢复

首次安装使用 README 的官方 bundle 管理流程，保留整个插件目录。归档中的表达式 patch 是分发源，宿主兼容预检需要先物化的字面路径；移动安装目录后重新准备副本并核对实际绑定位置。

本轮 SDK 0.2.1-rc.3 的官方本地目录安装实测保存 `link:<绝对目录>`，node_modules 中的真实路径仍指向传入目录；管理器不会替你执行本包的准备脚本。因此解压目录应长期保留，必须先在这个最终目录运行 prepare，不能安装后删除临时解压目录。其他版本若采用复制方式，需检查安装结果中的实际目录并在最终副本核对资源路径，不能把本轮 link 结果外推到所有版本。

完整分享包的全局规则与插件安装分开执行。`node scripts/install-workflow.mjs --home <绝对路径>` 默认只读；`--apply` 只追加受管区块并备份整个原文件。它不切换用户默认模式、不安装额外 hook、不更改模型或账号。单独插件 ZIP 只提供 Ultimate-Model 预设内的工作约束。受管区块已有本地修改时保留审查，不能把“升级包”当作覆盖个人规则的授权。

增量更新先对原包、当前包与新包逐文件比较。仅当当前文件与可追溯旧版一致时自动更新；定制、额外文件、未知来源或并发改变必须保留审查。不要覆盖全局 AGENTS、模型、凭据、MCP、其他 bundle 或个人状态。

DSH 组合中 Home 后层可覆盖 bundle 同 id 注册。已停用的个人预设保留；不要只凭相同 id 删除行。迁移旧受管 observer 时，保存整文件与逐行预像，保留 automaticReview/automaticSnapshot 等本机选择。仅当全局守卫已核对为同版本/同契约且真实验证覆盖时，才停用同一预设守卫；不能按名称或存在性假定等价。未知旧版保留审查，不自动关闭新保护；有界前台许可按真实execution共享消耗，不能由presence或工具参数制造授权。list_bundles、磁盘版本和 Tool.listTools 各有范围，不能单独证明运行正常。

EPERM 先定位具体文件、阶段和占用，短暂发布只在对象身份与字节不变时有限重试。native 依赖被持有、权限错误或目标被替换均不能用无界重试解决；不修 ACL、不停别人的任务。清理失败与提交失败分别记录，已提交元数据不能配合目录倒退造成混代。

本轮还复现了独立的一层：Node24默认测试 runner 派生子进程，在Windows只读沙箱内报 `spawn EPERM`。同一个单测试文件改用 `node --test --test-isolation=none calculator.test.mjs`，仍留在原只读沙箱，4/4完整测试通过，包含保护文件写入应失败的负例；没有提权或改变沙箱权限。该选项只改变Node测试的进程组织，不是关闭操作系统沙箱。用前核对当前Node版本的 `--help`；多文件测试共享进程后可能互相影响，依赖进程隔离的套件不能直接替换。参见[本轮Node24.19官方CLI说明](https://nodejs.org/download/release/v24.19.0/docs/api/cli.html#--test-isolationmode)。

读取 Shell 结果时核对命令实际exit、TAP测试总数、失败和跳过；本轮真实工具曾在 `isError=false` 的成功返回中包含子命令 exit1。派发成功、无工具异常都不等于测试通过。

模式按钮被遮挡时，先查看前景模态的来源。DSH 官方预览说明正常点击“继续”后才解除页面 inert；Vision Router 的“稍后”只关闭本页，刷新或新页面可能再次出现，右上“关闭”或该插件正常 Escape 路径才会持久记录已读。不要删除插件或关闭视觉能力来掩盖引导，也不要改 CSS、移除 inert 或 force 点击背景。选择工作区可能建立新会话并采用默认模式，因此在目标工作区绑定后再明确选择 Ultimate-Model，核对该会话实际组合。

卸载通过官方 remove_bundle，并检查组合后有没有独立 Home 注册。卸载不删除用户经验/检查点或其他新增内容。回退使用本次备份与当前预像比较，遇到并发改动保留恢复目录，不能覆盖新写入。需要重启采用时，等待当前用户确认维护窗口。

多文件协议是应用级可恢复事务，不是跨任意文件系统的原子性保证。Windows x64 已验证的范围与其他平台未验范围见验收报告。

这些规则和有限形式的工具守卫不能代替项目本身的权限、版本控制与备份。模型仍可能产生逻辑错误；正常用户文件编辑需要按任务归属与预像审查，不能把通过某个拦截测试解释为所有脚本及改删都已受控。
